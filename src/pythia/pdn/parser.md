# Модуль `pythia.pdn.parser`

Модуль читает партии из текста или файла в формате **PDN** (Portable Draughts
Notation) и проигрывает их на генераторе ходов, проверяя легальность записанных
ходов.

## Формат PDN

PDN-файл состоит из партий. Каждая партия — блок заголовков и текст ходов
(movetext):

```pdn
[Event "Rated Bullet game"]
[White "fred"]
[Black "bob"]
[Result "0-2"]

1. 32-28 19-23 2. 37-32 14-19 ... 0-2
```

- Заголовок — строка вида `[Key "Value"]` (регулярное выражение `HEADER_RE`).
- Movetext — произвольные строки с номерами ходов, полуходами и результатом.
- Поддерживаются комментарии `{...}`, строчные комментарии `; ...` и варианты
  `(...)`, в том числе вложенные скобки.
- Номера ходов (`1.`, `12...`), результаты (`1-0`, `0-1`, `1/2-1/2`, `0-2`,
  `2-0`, `*`) и аннотации `!`/`?` отбрасываются.

## Начальные позиции

- `STANDARD_START_FEN` — международные шашки (10×10): белые 31–50, чёрные 1–20.
- `RUSSIAN_START_FEN` — русские шашки (8×8): белые 21–32, чёрные 1–12.

Стартовая расстановка берётся из заголовка `[FEN "..."]`, если он присутствует,
иначе — по выбранному размеру доски. Цвет первого хода определяется позицией.

## Класс `PdnGame`

Результат разбора одной партии:

| Поле | Тип | Описание |
| --- | --- | --- |
| `headers` | `dict[str, str]` | Заголовки партии: `Event`, `White`, `Black`, `Result` и т.д. |
| `positions` | `list[str]` | Позиции в формате FEN/PDN. `positions[0]` — начальная, `positions[i]` — после i-го полухода. Цвет хода в каждой позиции — сторона, делающая следующий ход. |

## Класс `PdnParser`

### Создание

```python
parser = PdnParser(
    rules=Rules.INTERNATIONAL,   # правила варианта игры
    board_size=None,             # по умолчанию BIG (10×10) или STANDARD (8×8)
)
```

Параметры:

- `rules` — правила, влияющие на легальность ходов при replay. Поддерживаются
  `Rules.INTERNATIONAL` и `Rules.RUSSIAN`.
- `board_size` — размер доски. Если не задан, выбирается автоматически:
  `BoardSize.STANDARD` (8×8) для русских шашек и `BoardSize.BIG` (10×10) для
  остальных.

### Разбор партий

| Метод | Возвращает | Назначение |
| --- | --- | --- |
| `parse(text, progress=None)` | `list[PdnGame]` | Разбирает все партии из строки. |
| `parse_file(path, progress=None)` | `list[PdnGame]` | Разбирает все партии из файла. |
| `iter_parse_file(path)` | `Iterator[PdnGame]` | Лениво читает партии из файла по одной, не загружая его целиком в память. |
| `count_games(text)` | `int` | Быстро считает партии в строке без разбора ходов. |
| `count_games_file(path)` | `int` | Быстро считает партии в файле без разбора ходов. |

Правило разделения партий: новая партия начинается, когда после movetext
встречается строка заголовка. Партия без movetext (только заголовки) получает
единственную начальную позицию. Несколько блоков заголовков подряд без movetext
между ними относятся к одной партии.

### Прогресс разбора

`parse` и `parse_file` принимают необязательный колбэк:

```python
ProgressCallback = Callable[[int, int], None]  # (обработано, всего)
```

Если колбэк передан, парсер сначала быстро сканирует источник и считает общее
число партий (`count_games` / `count_games_file`), а затем вызывает
`progress(done, total)` после каждой разобранной партии. Это позволяет
показывать прогресс-бар или процент выполнения на больших файлах.

```python
def on_progress(done: int, total: int) -> None:
    percent = done * 100 // total if total else 100
    print(f"\r{done}/{total} ({percent}%)", end="", flush=True)

games = parser.parse_file("huge.pdn", progress=on_progress)
```

Особенности:

- Без `progress` лишнего прохода по файлу нет — используется ленивый итератор.
- С `progress` файл читается дважды потоково: сначала подсчёт, затем разбор.
- Подсчёт не создаёт досок и не генерирует ходы, поэтому значительно дешевле
  replay и пригоден для оценки объёма работы заранее.

## Как проигрывается партия

1. Создаётся `DamBoard` выбранного размера и устанавливается стартовая позиция
   (или `[FEN "..."]`).
2. Movetext очищается от комментариев и вариантов (`_strip_annotations`).
3. Каждый токен полухода преобразуется в путь полей и признак взятия
   (`_move_notations`).
4. Для текущего игрока создаётся генератор ходов (`_create_generator`:
   `InternationalMoveGen` или `RussianMoveGen`).
5. Ход из нотации сопоставляется с легальным ходом (`_match_move`). Сначала
   ищется точное совпадение пути, затем — совпадение по крайним полям (нотация
   взятия может не содержать промежуточных полей приземления, например
   `39x19` вместо `39x28x19`).
6. Ход выполняется (`do_move`), позиция сохраняется в `positions`.
7. Превращения в дамку и побитые фигуры вычисляются движком, а не берутся из
   нотации.

## Ошибки

- `ValueError("Нераспознанный токен хода: ...")` — movetext содержит токен,
  не являющийся ходом, результатом или номером.
- `ValueError("Недопустимый номер поля в ходе: ...")` — номер поля меньше 1.
- `ValueError("Номер поля вне доски WxH: ...")` — номер поля не существует на
  выбранной доске.
- `ValueError("Ход ... не определён однозначно (совпадений: N)")` — нотация
  не соответствует ровно одному легальному ходу.
- `ValueError("Правила ... не поддерживаются PDN-парсером")` — переданы
  неподдерживаемые правила.

## Пример

```python
from pythia.core.rules import Rules
from pythia.pdn.parser import PdnParser

parser = PdnParser(rules=Rules.RUSSIAN)
games = parser.parse_file("games.pdn")

for game in games:
    print(game.headers.get("White"), "-", game.headers.get("Black"))
    print("полуходов:", len(game.positions) - 1)
```
